# Сборка Space Cadet HD для Windows x64

В основе игры лежит SpaceCadetPinball 2.1.1 DEV, коммит `cb9b7b886244a27773f66b0b19fdc2998392565e`. Компоненты стола и классические правила начисления очков унаследованы из этой ревизии. В 7.0 движок рассчитывает остаток времени после каждого контакта, делит зеркальные взмахи флипперов на одинаковое число шагов и учитывает угловую скорость шара. Ориентация шара передаётся в HD-рендерер. [Исходная ревизия движка](https://github.com/k4zmu2a/SpaceCadetPinball/commit/cb9b7b886244a27773f66b0b19fdc2998392565e)

## HD 7.0.2

У верхнего левого бампера в тройке исправлена посадка подвижного корпуса относительно отверстия в столе. Его восемь HD-кадров (388–395) строятся в `tools/art-v2/render_parts.py`. Положение опоры и шляпки учитывает перспективу исходного стола. Игровая геометрия и события берутся из того же DAT.

## HD 7.0.1

На новом профиле выбран банк GeneralUser GS. Громкость темы равна 64 из 128, звуков стола — 128 из 128. При запуске музыка выключена. В настройках изображения можно переключить сглаживание контуров шара и отдельных деталей HD. В изображении плаката восстановлен край планеты у левой рамки. Английское описание ремастера, управление и игровые снимки находятся в `README.md` и `docs/screenshots`.

## HD 7.0

В [отчёте по физике](PHYSICS-HD7.md) приведены контрольные удары и девять запусков.
В [отчёте по звуку](AUDIO-HD7.md) указаны форматы, число одновременно звучащих эффектов и измерения перегрузки. В [описании музыкального банка](tools/BONUS-MUSIC.md) приведена команда для пересоздания дополнительного звучания темы из оригинального MIDI.

В центральном диске разряд охватывает всю выбранную прожилку за 0,38 с и оставляет затухающий след. В скрытом окне 900 × 624 при активном Windows HDR контрольная точка в пике показала 208,34 нита. Когда её закрывал шар, в обеих фазах там измерено 148,56 нита. Внешние прожилки используют прежнюю анимацию.

Для полной сборки скопируйте из дистрибутива папки `Data`, `HD`, `Music` и `Licenses` в каталог EXE. В архиве восстановления это автоматически делает `Restore.ps1 -Action Build`.

## Движок

Проверенная конфигурация — Visual Studio 2022 с компонентами C++ для настольных приложений и Windows SDK, MSVC x64, CMake 3.22.2, SDL 2.32.10 и SDL_mixer 2.8.1. Распакуйте архивы `SDL2-devel-2.32.10-VC.zip` и `SDL2_mixer-devel-2.8.1-VC.zip` в папку `deps` в корне исходников. [Релиз SDL](https://github.com/libsdl-org/SDL/releases/tag/release-2.32.10) · [Релиз SDL_mixer](https://github.com/libsdl-org/SDL_mixer/releases/tag/release-2.8.1)

Откройте PowerShell в корне исходников и соберите игру.

```powershell
$sdlPath = (Resolve-Path .\deps\SDL2-2.32.10).Path
$mixerPath = (Resolve-Path .\deps\SDL2_mixer-2.8.1).Path
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 "-DSDL2_PATH=$sdlPath" "-DSDL2_MIXER_PATH=$mixerPath" "-DCMAKE_WIN32_EXECUTABLE:BOOL=ON"
cmake --build build --config Release --parallel
```

Вместо двух команд CMake с теми же каталогами можно запустить `.\BuildForWindows.ps1`. Для собранного EXE нужна среда выполнения MSVC 2015–2022 x64. В готовой папке игры её библиотеки лежат рядом с программой.

В `bin\Release` появятся `SpaceCadetHD.exe`, `SDL2.dll` и `SDL2_mixer.dll`. Для запуска скопируйте туда папки `Data` и `HD` из игровой сборки. Чтобы воспроизвести комплект из исходных ресурсов, заполните `Data` следующей командой и соберите `HD` по разделу ниже.

```powershell
$gameData = New-Item -ItemType Directory -Path .\bin\Release\Data -Force
Get-ChildItem -LiteralPath 'C:\Games\pinball' -File | Where-Object Extension -In '.DAT', '.WAV', '.MID' | Copy-Item -Destination $gameData.FullName
```

Проверенный `PINBALL.DAT` занимает 928 700 байт. SHA-256 — `42DEFD5D2A339A3953FE643716AFF4E35B2CEA7A3E54505C82D1E78D5325BC04`. Комплект содержит 60 WAV. Для шести имён из DAT соответствующие файлы отсутствуют в исходной копии — SOUND2, SOUND37, SOUND44, SOUND52, SOUND59 и SOUND62, все с расширением WAV. Музыка находится в `PINBALL.MID`. Файл `PINBALL2.MID` содержит растровый шрифт.

## Текстуры ×4

В папке `tools/art-v2` лежат два зафиксированных изображения для сборки. `board-source.png` — перерисованное поле, совмещённое с игровыми координатами. `backglass-generated.png` — иллюстрация панели приборов. Сборка использует эти изображения локально. Номера кадров, положения объектов и размеры табло берутся из Windows DAT.

Подготовьте Python 3.10 x64 и установите зависимости в отдельное окружение. На машине сборки использовались Python 3.10.10, PyTorch 2.5.1+cu121, NumPy 1.22.4, SciPy 1.8.1, Pillow 10.0.0 и GeForce RTX 4080. Команды ниже используют CUDA 12.1. Для CPU используйте для PyTorch индекс `https://download.pytorch.org/whl/cpu`. При расчёте базового слоя CUDA использует FP16, CPU — FP32, поэтому отдельные значения цвета могут отличаться. Для надписи BALL на приборной панели опубликованная версия использует системный шрифт Bahnschrift. При его отсутствии генератор использует установленный DejaVu Sans.

```powershell
py -3.10 -m venv .venv
$python = (Resolve-Path .\.venv\Scripts\python.exe).Path
& $python -m pip install numpy==1.22.4 scipy==1.8.1 pillow==10.0.0
& $python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu121
```

Сохраните веса `realesr-general-x4v3.pth` в корне исходников. SHA-256 — `8DC7EDB9AC80CCDC30C3A5DCA6616509367F05FBC184AD95B731F05BECE96292`. Генератор проверяет веса и исходный DAT перед работой. [Файл весов Real-ESRGAN](https://github.com/xinntao/Real-ESRGAN/releases/download/v0.2.5.0/realesr-general-x4v3.pth)

```powershell
& $python .\tools\art-v2\bake.py .\bin\Release\Data\PINBALL.DAT .\bin\Release\HD --weights .\realesr-general-x4v3.pth
```

Сначала `tools/upscale.py` создаёт временную базу из 318 BMP. Затем `render_parts.py` строит детали и прорисовывает 116 погашенных вставок на поле. Генератор рассчитывает маски покрытия при четырёхкратном разрешении. Карта глубины из DAT определяет, какую часть линзы закрывают борта и направляющие. В конце `bake_backglass.py` собирает панель приборов. В HD 4 получается 630 BMP. Это 318 исходных номеров групп, четыре дополнительных кадра разряда, два атласа флажков и 306 масок.

При работе над деталями базу стоит сохранить. Следующие две команды воспроизводят те же этапы по отдельности. После изменения материала или рисунка достаточно второй команды.

```powershell
& $python .\tools\upscale.py .\bin\Release\Data\PINBALL.DAT .\realesr-general-x4v3.pth .\build\HD-base
& $python .\tools\art-v2\bake.py .\bin\Release\Data\PINBALL.DAT .\bin\Release\HD --base .\build\HD-base
```

Для замены исходной живописи приложен `tools/art-v2/register_board.py`. Он принимает три пути — референс оригинального поля 730 × 940, новую иллюстрацию и имя выходного PNG 1460 × 1880. Для этой операции дополнительно установите `opencv-python-headless==4.10.0.84`. В стандартную сборку уже входит совмещённое поле.

В HD 3 отдельные спрайты и неподвижная часть стола совместно задают геометрию девяти откидных мишеней. Два флажка вращаются вокруг фиксированных осей. Для восьми положений плунжера меняется шаг стальной пружины при фиксированной нижней опоре. В иллюстрации приборной панели отредактирована только область глаз пилота.

В HD 4 для каждого флажка создаётся атлас из 32 положений вокруг его оси. Отображение следует за временем до очередного исходного события вращения. Игровая логика продолжает обрабатывать восемь штатных положений. Маска бортов строится по прямым в перспективе. Видимая область линзы определяет и форму её усиления в HDR.

В HD 5 `route_inserts.py` строит отдельные перспективные контуры для 23 указателей миссий. Их вершины восстановлены по разнице горящего и погашенного кадров в оригинальном DAT. При подготовке сиреневой рампы `purple_ramp.py` переносит мелкий рисунок поверхности с верхней дуги на соседнюю пластину. Наклон красной линзы lite198 задан по её цветному контуру. В проверочном прогоне файлы `detail5-dat-*.bmp` и `detail5-hd-*.bmp` показывают соответствующие состояния в обоих режимах графики.

`TableRelief.cpp` строит из карт глубины поверхность в координатах камеры и обновляет изменившиеся участки при движении механизма. Для видимых точек шара `HdRenderer.cpp` вычисляет отражённые лучи и ищет пересечения с этой поверхностью на CPU. Обратное отражение шара в металлических деталях вычисляет `RailReflections.cpp`. Ракурс камеры совпадает с оригиналом. Анимации галактик и электрических дуг реализованы в `CabinetEffects.cpp`, движение импульсов по рисунку стола — в `FieldTraces.cpp`.

## Параметры игры

HD 4 сразу запускает новую партию со штатной световой последовательностью. При первом запуске выбрана «Классика», включены звуки стола и выключена музыка. Флажок «Медитативный» рядом с кнопкой «Играть» запоминается между запусками. В этом режиме топливо сохраняется, боковые пружины готовы к повторному срабатыванию, а своевременный удар может достать шар, который прошёл бы мимо обоих кончиков. Без удара шар падает. Толчки стола ослаблены и ограничены по частоте. Результат в пятёрке записывается на диск в момент окончания партии и повторно при подтверждении нового имени. На экране рекордов две вкладки. Их можно переключать мышью или плечевыми кнопками геймпада. Обе таблицы совместимы с профилями HD 2 и HD 3.

Esc открывает меню, F2 начинает новую партию, F3 ставит её на паузу. F7 перебирает доступные размеры с шагом 0,5×, полный экран и исходный размер. Размер первого окна подбирается под рабочую область экрана. F4 и двойной щелчок переключают полный экран. В меню управления действие можно привязать к нажатой клавише, кнопке мыши или геймпада. По умолчанию Shift слева и справа либо бамперы геймпада управляют флипперами. Правый стик задаёт натяжение пружины, возврат к центру запускает шар. Левый стик толкает стол влево, вправо или снизу. Оба жеста можно отключить отдельно.

Язык интерфейса и сообщений стола можно переключить между русским и английским во время партии. Информационная область и дисплей миссий рисуют текст точечным шрифтом из `CabinetDisplay.cpp`. Два цвета линз взяты из палитры цифр штатного счётчика. Для каждого окна слова переносятся внутри его размеров из DAT, а активные точки получают усиление в HDR.

## HD 6

F1 открывает помощь на текущем языке. Вступительную иллюминацию можно завершить пробелом. После окончания партии пробел начинает следующую. В игре он сохраняет назначение пружины. Основа сине-фиолетовой матрицы сверена с цветом счётчика из оригинального Windows-пинбола.

В tools/art-v2/lane_detectors.py строятся неподвижные гнёзда и подвижные язычки одиннадцати дорожек. Исходные датчики и игровой код столкновений задают их положения и состояния. cabinet_sky.py отвечает за печать двух маленьких галактик. Движение неба и редкие вспышки находятся в CabinetEffects.cpp, дыхание центрального диска — в FieldTraces.cpp.

## HD 6.1

При потере фокуса или сворачивании останавливается ход игры. Возвращение из автоматической паузы, продолжение через F3, меню или справку запускает три секунды отсчёта по монотонным часам SDL. На сигнале «ВПЕРЁД!» возобновляются игровые таймеры и физика. Оформление отсчёта находится в `ResumeOverlay.h`. Полный экран использует текущий режим рабочего стола.

У анимации пружины 113 положений, включая восемь исходных поз. Атлас `HD/plunger-motion.bin` строится вместе с BMP. В медитативном режиме допуск касания при ударе кончиком расширен на 6% диаметра шара. Выхлоп на постере повторяется каждые 38–54 секунды игрового времени. Две фары кратко поблёскивают примерно раз в две минуты.

Подсказки F1, Esc и F4/F7 видны под табло во время всей партии. Диоды букв сравниваются с цифрами на одном кадре: измеряются их яркость и цвет в линейном FP16-буфере scRGB при 600, 900 и 1200 пикселях по ширине. Для бесшумного запуска проверок установите в PowerShell `$env:SDL_AUDIODRIVER = "dummy"`. С этим параметром звуковой микшер обрабатывает музыку и эффекты через виртуальный выход.

В стандартной HD-папке 631 BMP. Скрипт `bake_planet.py` строит карту поверхности зелёной планеты из мастер-рисунка постера. Полный оборот занимает 300 секунд игрового времени. Четыре звезды на постере поочерёдно вспыхивают на 1,85 секунды. У центрального круга сохраняется освещённая середина на обеих фазах цикла. Проверка классических правил использует ту же эталонную запись 2400 шагов.

В архиве восстановления файл `Recovery/Reference/plunger-HD6.csv` записан предыдущей версией HD 6. Проверочный сценарий воспроизводит пять оттяжек кнопкой и четыре аналоговым стиком, в том числе частичное обратное движение до отпускания. Для повторения запустите EXE с `-verify -sw -reset` в отдельном процессе с переменными `SPACECADET_VERIFY_LAUNCH=1`, `SPACECADET_VERIFY_DIR` (существующий отдельный каталог), `SDL_VIDEODRIVER=dummy` и `SDL_AUDIODRIVER=dummy`. Сравните появившийся `launch.csv` с эталоном. Он содержит 3296 шагов, силу пружины, порог срабатывания, положение шара, направление, скорость и счёт. SHA-256 эталона — `6ae4d97745606512dfe10324fcfa23af7590d8d1e6b5c13058f976de712b06c2`.

## HD 6.2

В настройках игры появилась сохраняемая опция «Таймер после паузы». По умолчанию она включена. Цифры «3», «2», «1» занимают по 700 мс, надпись «ВПЕРЁД!» или «GO!» — 400 мс. В заключительные 300 мс игрок видит свободное поле, шар и игровые таймеры всё ещё стоят. Перед продолжением краткая световая метка один раз указывает на положение шара. При выключенной опции игра возобновляется сразу.

Обновлены маски кириллицы светодиодного табло. Вид буквы задают координаты включённых диодов. Размер, цвет и яркость отдельного диода по-прежнему задаёт та же оптика, что и у счётчика очков. Английские буквы по-прежнему рисуются по исходному шрифту `PB_MSGFT`.

У обеих панелей шаг матрицы постоянный. Короткие сообщения занимают одну строку, длинные переносятся на доступные строки. Если сообщение не помещается на панели целиком, остаток показывается на следующей странице. Проверка `MatrixLayoutChecks62.h` охватывает раскладку строк и постраничный показ.

Пробел возобновляет игру после ручной паузы на F3. В открытом меню пробел подтверждает выбор. Чтобы проверить сохранение галочки после перезапуска, выполните два последовательных запуска с одним отдельным `SPACECADET_VERIFY_DIR` и `SDL_AUDIODRIVER=dummy`. В первом задайте `SPACECADET_SCORE_TEST=settings-write` и ключи `-verify -reset`. Во втором задайте `SPACECADET_SCORE_TEST=settings-read` и ключ `-verify`.

После затухания вращения левый флажок доворачивается на своей оси в видимое положение покоя. Это заключительная фаза HD-анимации. Очки по-прежнему начисляет исходный игровой механизм. Проверка положения покоя находится в `SpinnerRestChecks62.h`.

У правой группы из трёх жёлтых мишеней уточнены контуры направляющей и самих мишеней. Изменены фон `107.bmp`, три спрайта `432.bmp`–`434.bmp` и их маски. Все семь изображений восстанавливаются из включённого в архив рецепта.

## HD 6.3

У кириллических «Ы» и «ы» правая стойка придвинута к чаше в пределах сетки табло. Новая редакция использует тот же шаг диодов, что и другие русские и английские глифы.

Для оформления стола и постера используется отдельный отсчёт времени. При игровой паузе галактики, зелёная планета, выхлоп и световой блик на названии продолжают движение. Положение шара и время миссии сохраняются. Проверку расхождения двух часов выполняет `PausedArtChecks63.h`.

Рисунок центрального диска входит в фон `107.bmp`. Стартовая подсветка двух звёзд у флипперов и вращение красного звёздного пояса вокруг каждой из трёх галактик отрисовываются в движке. Для этих эффектов в проверочном режиме предусмотрены `StarStripChecks63.h` и `GalaxyBeltChecks63.h`.

## HD 6.3.1

У двух звёзд за флипперами свет заполняет ширину нарисованных полос. Во время стартового шоу и ожидания запуска шара яркость меняется в ровном ритме. Галактики вращаются медленнее, каждая со своим внешним поясом. Момент запуска определяет игровой код, а свечение и вращение рассчитывает рендерер. Для сборки используются те же графические ресурсы, что и в HD 6.3.

При проверке в окне 1200 × 832 в HDR максимальная яркость пурпурной полосы в scRGB-буфере составила 63,64 нита, фиолетовой — 49,47 нита. На том же мониторе исходная 6.3 дала 68,94 и 52,55 нита соответственно. Пик двух штатных контрольных ламп составил 399,38 нита в обеих сборках.

Кнопка разворачивания окна Windows включает штатный полноэкранный режим игры. Возврат по F4 проверяется в `MaximizeChecks631.h`.

## HD 6.3.2

Пурпурная и фиолетовая обводки у флипперов передают свет друг другу каждые 0,6 секунды. Во время стартового шоу, подачи и ожидания запуска они следуют общим часам оформления. Для сравнения с плавным дыханием обводок из 6.3.1 задайте переменную среды `SPACECADET_BREATHE_STAR_OUTLINES=1` перед запуском. Дыхание центрального диска работает независимо. Внутри диска проходят короткие световые импульсы по прожилкам.

Для отсчёта после паузы проверяется положение шара в игре. Если шар ещё ожидает подачи или остаётся в пусковой дорожке после слабого удара пружины, возобновление происходит сразу. Для шара на игровом поле действует обычная настройка таймера.

Чтобы отдельно измерить свет, укажите свежий профиль в `SPACECADET_VERIFY_DIR`, задайте `SPACECADET_VERIFY_DOME_HDR=1` и `SDL_AUDIODRIVER=dummy`, затем запустите EXE с `-verify -reset` на мониторе с активным Windows HDR. Этот сценарий работает в скрытом окне. В файле `report.txt` он сохраняет яркость выбранных пикселей кадрового буфера FP16 в нитах. В проверенной сборке прожилка в окне 900 × 624 дала рост с 52,72 до 114,08 нита. При перекрытии шаром яркость той же точки составила 57,32 нита в обеих фазах. В окне 1200 × 832 пики обводок составили 63,64 и 49,47 нита, штатной лампы — 399,38 нита.

## Проверка

В PowerShell из корня исходников запустите две партии с изолированными профилями. Отпечатки траектории, счёта и ламп пишутся в `trace.csv`, результаты проверок — в `report.txt`. Проверочный прогон также сохраняет SDR-снимки для сравнения графики.

```powershell
$exe = (Resolve-Path .\bin\Release\SpaceCadetHD.exe).Path
$env:SDL_AUDIODRIVER = 'dummy'
$env:SDL_VIDEODRIVER = 'dummy'
try {
    foreach ($mode in 'classic', 'meditative') {
        $qaProfile = New-Item -ItemType Directory -Force -Path ".\build\qa-$mode"
        $env:SPACECADET_VERIFY_DIR = $qaProfile.FullName
        $testArgs = @('-verify','-sw','-reset')
        if ($mode -eq 'meditative') { $testArgs += '-meditative' }
        $game = Start-Process -FilePath $exe -ArgumentList $testArgs -WindowStyle Hidden -Wait -PassThru
        Get-Content -LiteralPath (Join-Path $qaProfile.FullName 'report.txt')
        if ($game.ExitCode -ne 0) { throw "Сбой проверки $mode, код $($game.ExitCode)" }
    }
} finally {
    Remove-Item Env:SPACECADET_VERIFY_DIR -ErrorAction SilentlyContinue
}
Get-FileHash .\build\qa-classic\trace.csv -Algorithm SHA256
```

Сравните `trace.csv` с `Recovery/Reference/classic-HD7.csv`, а `launch.csv` с `Recovery/Reference/plunger-HD7.csv`. Эти файлы записаны версией 7.0. Для исторического сравнения сохранены траектории исходного движка и девять запусков HD 6. Из-за изменений в физике их координаты после первого удара могут расходиться с HD 7.

Проверки охватывают окно и F7, переключение HDR, звуковой микшер, виртуальные Xbox и DualSense с аналоговыми стиками, проход по центру, запоздалый удар флиппера, повторное срабатывание обеих пружин, топливо, изменение счёта и состояния ламп. Для проверки вывода на мониторе включите HDR в Windows, оставьте HDR включённым в игре и найдите в отчёте строку `DXGI HDR active`. Указанный пик вычисляется по измеренному содержимому FP16-буфера. Оптическую яркость панели можно измерить внешним прибором.

Проверка смены языка сохраняет идентификаторы сообщений, очередь, таймеры и числовые подстановки. В `game-ru.bmp` и `game-en.bmp` можно сравнить одни и те же игровые индикаторы. На HDR-мониторе прогон отдельно измеряет излучение обеих матриц и фон между точками. Строки Fullscreen HDR information panel и Fullscreen HDR mission panel содержат пики двух табло и минимум между светодиодами в FP16-буфере.

Проверка сохранения выполняется двумя запусками с одним тестовым профилем. Для первого установите SPACECADET_SCORE_TEST=write и запустите EXE с -verify -reset. Для второго установите SPACECADET_SCORE_TEST=read и запустите тот же EXE с -verify. Отчёты profile-write.txt и profile-read.txt включают проверку имени на русском, автоматической записи второго результата, мыши и плечевых кнопок Xbox и DualSense. Для полного теста стола удалите эту переменную из окружения.
